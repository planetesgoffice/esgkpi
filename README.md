# 普萊德 永續 KPI 管理平台｜網站檔案

## 檔案
| 檔案 | 用途 | 需要修改嗎 |
|---|---|---|
| index.html | 網站頁面 | 不用 |
| app.js | 畫面與填報流程 | 不用 |
| graph.js | Microsoft 365 登入與 Excel 讀寫 | 不用 |
| msal-browser.min.js | Microsoft 官方登入元件（@azure/msal-browser 3.27.0） | 不用 |
| config.js | 三個設定值 | **要**，依設定步驟填入 |

## 架構
- 純靜態網頁，沒有後端伺服器、沒有資料庫。
- 使用者用公司 Microsoft 365 帳號登入（MSAL，授權碼＋PKCE），網站以「登入者本人」的權限，透過 Microsoft Graph 讀寫 Teams 文件庫中的「永續KPI資料.xlsx」。
- 不含任何密碼或 Client Secret。config.js 裡的 Tenant ID、Client ID 不是機密。
- 網站不保存資料副本；只有在「登入過期需要重新登入」時，會把尚未儲存的填報內容暫存在該瀏覽器分頁，登入回來後還原。

## 部門異動
過去年度的 KPI 保留當時的部門名稱。組織調整時，在 Excel「部門」表把舊部門設為停用並填寫「改為」；網站的部門選單只列出啟用中的部門，複製上一年度時自動換成新代碼。

## 需要的 Microsoft Graph 權限（委派）
- User.Read：讀取登入者的姓名與信箱，用來對應人員名單
- Files.ReadWrite.All：讀寫登入者有權限的 Excel 檔（實際能存取哪些檔案，仍受 SharePoint 權限限制）

## 資料安全說明（方案 A）
網站上的限制（例如只有管理者能維護人員名單）只作用在網站畫面。所有團隊成員對 Excel 都有編輯權，直接開 Excel 仍可修改任何資料。異動可由 Excel 的版本歷程與「填報人／最後修改人」欄位追溯。

## 防止資料覆蓋與錯誤處理
- 每月填報只「新增列」，不覆蓋舊資料；同一 KPI＋月份以填報時間最新的一列為準。
- 儲存前重新讀取 Excel，若有人在你開啟後已更新同一月份，會停下來提示，不會覆蓋。
- 同一時間只送出一個寫入請求（官方建議）。
- 寫入後重新讀回 Excel 確認，確認成功才顯示「已儲存」。
- 逾時時先確認是否其實已寫入，避免重複新增。
- 修改 KPI／人員時，以「系統識別碼」或英文名找到列，寫入前再核對一次該列，Excel 被排序過就拒絕寫入。
